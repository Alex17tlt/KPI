## Что нужно для запуска

- Node.js **22.13.0 или новее** и npm.
- Интернет для установки зависимостей из `package-lock.json`.
- Windows, macOS или Linux.

Сначала распакуйте ZIP целиком. Откройте терминал в папке `Seven_Finance_KPI`, где лежит `package.json`. Сохраняйте вложенные каталоги и файлы, включая `.openai/hosting.json`: этот файл нужен сборке.

### 1. Установить зависимости

```sh
npm run install:ci
```

Дождитесь завершения команды. Каталог `node_modules` создастся автоматически.

### 2. Собрать проект

```sh
npm run build
```

Сборка создаёт конфигурацию локального Worker: `dist/server/wrangler.json`.

### 3. Создать таблицы новой локальной базы

Выполните эту команду один раз для новой локальной базы после первой успешной сборки:

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_peaceful_proteus.sql
```

Это создаёт локальные таблицы по сохранённой схеме. Команда не переносит данные работающего сайта. Не применяйте ту же начальную SQL-миграцию повторно к уже созданным таблицам.

### 4. Запустить приложение

```sh
npm run dev
```

Откройте адрес из терминала — обычно `http://localhost:5173`.

Для локального входа откройте на том же адресе путь `/signin-with-chatgpt?return_to=/`, например:

```text
http://localhost:5173/signin-with-chatgpt?return_to=/
```

В чистой локальной установке используется встроенная имитация входа с пользователем `local_seedy`. Первый вошедший пользователь пустой базы получает роль владельца. Этот механизм предназначен для локальной разработки. После входа можно создать месяц и проверить работу интерфейса.

Остановить сервер можно сочетанием `Ctrl+C` в терминале.

Команда `npm start` доступна для локального запуска собранного Worker, но она не имитирует вход. Для обычного локального ознакомления используйте `npm run dev`.

## Перенос на другой хостинг

Это приложение с серверной частью и базой Cloudflare D1. Для развёртывания нужны сборка Worker, подключённая база с binding `DB` и применение SQL-миграций.

На работающем сайте вход и доверенные заголовки пользователя обеспечивает ChatGPT Sites. При переносе вне Sites разработчику нужно подключить собственный доверенный механизм авторизации и согласовать его с `app/chatgpt-auth.ts` и `lib/server.ts`. Пользовательские заголовки из внешнего запроса нельзя принимать как подтверждение личности без такой проверки.

В `.openai/hosting.json` сохранён идентификатор исходного проекта. При создании отдельного нового Site ему должен быть назначен собственный идентификатор; не публикуйте изменения в исходный проект случайно.

## Данные и комплектность

В архив входят код, схема базы, миграции, зависимости в виде списка и lockfile, тесты, скрипты и статические файлы. Готовые установленные пакеты `node_modules`, результаты сборки `dist`, Git-история, локальные кэши и секреты окружения в архив не входят.

Сохранённые месяцы, отметки выполнения, замечания, участники, роли и журнал действий работающего сайта находятся в его базе D1. Архив исходного кода не является резервной копией этой базы. Для переноса существующих записей нужна отдельная выгрузка данных с последующим импортом в новую среду.

`SOURCE_INFO.json` фиксирует происхождение и версию исходников. `SHA256SUMS.txt` содержит контрольные суммы всех остальных файлов архива.
